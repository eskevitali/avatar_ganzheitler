# Пакет куклы v1

Приложение — отдельный движок визуализации: фиксированный пульт, TalkingHead/Three.js и речь ElevenLabs. Профиль меняет модель и её настройки губ/мимики. Голос ElevenLabs остаётся общей серверной настройкой. Новая художественная модель в эту работу не входит; в поставке есть только исходная учебная кукла.

## Установка без правки кода

Подготовьте папку с двумя файлами: `profile.json` и самодостаточным `model.glb` (текстуры и буферы внутри). Манифест:

```json
{
  "formatVersion": 1,
  "id": "my-avatar-v1",
  "name": "Моя кукла",
  "model": "model.glb",
  "body": "F",
  "cameraView": "head",
  "defaults": {
    "mood": "neutral",
    "lips": {
      "PP": {"viseme_PP": 1, "jawOpen": 0.02},
      "aa": {"viseme_aa": 1, "jawOpen": 0.85},
      "O": {"viseme_O": 1, "mouthFunnel": 0.8},
      "I": {"viseme_I": 1, "mouthSmileLeft": 0.7, "mouthSmileRight": 0.7}
    }
  }
}
```

Из корня репозитория:

```sh
node scripts/install-profile.mjs /absolute/path/to/package
```

Установщик проверяет пакет и атомарно добавляет `public/profiles/<id>/`; существующий профиль не перезаписывается. Для новой версии используйте новый id. Файлы пакетов не включаются в Git автоматически. Обновите страницу и выберите профиль. При стандартной Docker-сборке устанавливайте пакет **перед сборкой**: `COPY public` включит его в образ. Сервер обнаруживает папки автоматически; перезапуск при локальной установке не нужен. Установка — операция администратора на файловой системе, веб-загрузка и архивы в v1 не предусмотрены. Пакет не содержит исполняемого кода.

`formatVersion`, `id`, `name`, `model`, `body` обязательны. Id: строчные латинские буквы, цифры, дефис, начинается с буквы, до 64 символов; `training` зарезервирован. Имя до 100 символов; модель — имя файла GLB без пути. `body`: F/M (шаблоны поз TalkingHead), `cameraView`: head/upper/mid/full, по умолчанию head. Мимика: neutral/happy/sad/angry/fear. Значения губ — конечные числа 0–1. Формы PP/aa/O/I и ключи соответствуют `public/profiles.mjs` и `public/mouth.mjs`; неполные настройки дополняются исходными значениями.

## Контракт модели и проверка

Контракт привязан к **встроенной версии** `public/vendor/talkinghead.mjs`, а не к произвольной последней версии TalkingHead. Источник требований — `showAvatar`, построение `posePropNames`, IK и таблицы morphs в этом файле. При обновлении движка пересмотрите адаптер и выполните тесты.

Нужен GLB 2.0, активная сцена с корнем `Armature`, внутри него полный именованный rig: Hips, Spine, Spine1, Spine2, Neck, Head; для Left/Right — Eye, Shoulder, Arm, ForeArm, Hand, UpLeg, Leg, Foot, ToeBase и HandThumb/Index/Middle/Ring/Pinky с суффиксами 1–3. Имена регистрозависимы. TalkingHead использует эти узлы даже для вида head. Масштаб в метрах, корректные позиции костей и уровень глаз обязательны для камеры и анимации. Совпадение имён не гарантирует правильную ориентацию, скиннинг и художественное качество: необходим визуальный просмотр.

Нужны настоящие morph targets в mesh под Armature с `extras.targetNames`. Полный машинно-проверяемый список `requiredMorphs` экспортируется из `profile-store.mjs`. Он включает viseme_PP/aa/O/I, jawOpen, mouthClose/Funnel/Pucker/SmileLeft/SmileRight/StretchLeft/StretchRight и формы глаз, бровей, губ для пяти эмоций. `mouthOpen` TalkingHead синтезирует из jawOpen. Значения должны действительно деформировать соответствующие части лица, это проверяется визуально. Произвольное переименование форм, VRM и альтернативный rig требуют отдельного адаптера и не поддерживаются пакетом v1. Сжатие/обязательные расширения и внешние ресурсы отклоняются: экспортируйте обычный самодостаточный GLB.

Проверки выявляют неизвестную версию, неверные поля/диапазоны, повреждённый заголовок, отсутствующие узлы/morphs и внешние ресурсы. Установщик выводит причину и не публикует невалидный пакет. Если пакет скопирован вручную и испорчен, `/api/profiles` исключает его из выбора и пульт показывает причину. Ошибки загрузчика браузера показываются в статусе; предыдущая кукла остаётся рабочей. Это проверка совместимости, не полноценный glTF Validator или проверка безопасности недоверенных 3D-файлов; устанавливайте проверенные автором ресурсы.

## Сохранение и переключение

Ползунки меняют позы М/А/О/И и их использование во время речи; выбранная эмоция относится к текущему профилю. Нажмите «Сохранить губы и мимику профиля» для записи на сервер. Сервер хранит карту по id в `/data/settings/profiles.json` рядом с существующим `tts.json`; путь переопределяется `PROFILE_SETTINGS_PATH`. Настройки общие для авторизованных пользователей этого инстанса, как и существующий голос. Секретов в файле профилей нет. При ошибке записи интерфейс сообщает об этом. Несохранённые изменения переживают переключение в текущей вкладке, но не обновление страницы. После обновления стартует учебный профиль, сохранённые настройки всех установленных профилей остаются доступны.

Во время генерации/воспроизведения и повтора переключение заблокировано. Отключите повтор, дождитесь конца фразы и выберите другую куклу. Переключение создаёт новый экземпляр TalkingHead, затем освобождает старые renderer, AudioContext и DOM; фиксированные формы и внутренняя мимика старой куклы не переносятся. Кэш аудио сохраняется, параметры рта вычисляются заново для текущего профиля. При неудаче новая сцена освобождается, старая остаётся.

## Проверки и локальный preview

```sh
node --test test/profiles.test.mjs
# При работающем preview и установленном Playwright/Chrome:
PLAYWRIGHT_MODULE=/path/to/node_modules/playwright CHROME_PATH=/path/to/chrome node test/browser-check.mjs
```

Браузерная проверка временно устанавливает явно помеченный тестовый профиль с учебной моделью и удаляет его после проверки. Это fixture, не новый аватар. Проверяются вход, выбор, индивидуальные значения, сохранение/перезагрузка, неудачная загрузка, сохранение старой куклы, речь/повтор/кэш с синтетическим аудио без платных запросов, один canvas и отсутствие ошибок JavaScript.

Для локального HTTP-preview выполните `node scripts/local-preview.mjs`. При первом запуске он создаст `.local-preview/access.txt` с отдельным паролем и `.local-preview/secret.txt` со случайным ключом, права 600. Пароль для входа прочитайте локально из access.txt. По умолчанию сервер слушает `0.0.0.0:3100`, настройки изолированы в `.local-preview`. Эта папка игнорируется Git. `DEV_HTTP=1` отключает только атрибут Secure у session-cookie для доступа по HTTP в доверенной LAN. В production сохраняйте HTTPS и не задавайте DEV_HTTP. Preview не содержит ключа ElevenLabs, пока он явно не задан окружением. Локальная HTTP-сеть не даёт защищённого транспорта пароля.

## Границы дальнейшей работы

Будущий вход — готовый текст (возможно JSON), затем ElevenLabs и визуализация. Протокол входа пока не определён и здесь не реализован. LLM, очереди, кодирование видео и доставка в OBS/Zoom/YouTube отсутствуют. Целевая художественная кукла из голубых/бирюзовых нитей и сцена зала потребуют отдельной модели/слоёв и проверки того же rig/morph-контракта. Файлы Templ с референсами этой реализацией не изменяются.
